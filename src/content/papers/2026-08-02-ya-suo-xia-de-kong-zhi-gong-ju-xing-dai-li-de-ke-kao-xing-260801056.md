**动机** 工具型语言模型代理不仅依赖任务提示，还持久使用系统侧控制上下文（ACC）定义工具、参数、策略、规划、输出与恢复规范。压缩这些控制上下文可降低 token 成本，但现有压缩评估多聚焦问答、推理或文本保真度，未衡量代理环境执行可靠性。长上下文模型对信息位置敏感，长度减少不等于操作安全，因此需要将 ACC 压缩重新定义为运行时可靠性问题。

**方法关键点**
- 构建 CompressAgent 基准：9 个独立构造的 ACC（覆盖工具使用、策略合规、协议引导三类任务），225 个留出测试任务，3 个固定 Qwen API 模型，6 档保留上下文预算（10%–100%），共 15,525 次逻辑运行。
- 四种主要压缩方法：机械截断（MT）、通用 LLM 改写（GLR）、基于节选的压缩（SBC）、义务感知压缩（OAC）。OAC 自动提取六类控制义务，贪心选择依赖闭包内的高权重义务，并给出可行性标记（Feasible/Best-Effort）。另含 LLMLingua 作为通用基线。
- 评估通过确定性沙盒执行，以环境验证成功为二元指标，并记录工具执行失败、动作解析失败等模式，不使用 LLM-as-judge。

**关键结果**
- 在 75% 保留预算时，GLR 和 SBC 分别达 92.7% 和 92.4% 成功率，接近全上下文的 93.8%，且 token 成本降低约 20%。
- 50% 预算处 SBC 仍达 67.9%，OAC 49.5%，GLR 骤降至 37.8%；到 35% 时 SBC 47.0%、OAC 39.0%、GLR 19.9%，方法分化剧烈。25% 以下所有方法进入失效区（最高 21.2%）。
- 失效模式分析显示 79.7% 为工具执行错误，20.0% 为动作解析错误，压缩实质改变了代理的失效模式。LLMLingua 在 50% 预算仅 10.0% 成功，且解析失败严重，表明通用标记压缩无法保留可执行接口。
- 不同 ACC 下方法效果差异显著，不存在全局最佳压缩器；OAC 自动义务保留与成功率相关系数 r=0.669，可行性标记虽非安全担保，但可将压缩从盲目缩短变为可审计的容量决策。
