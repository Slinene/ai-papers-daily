## 核心思路

层级 Semantic ID（SID）由粗到细：首层大致对应类目，后几层逐步细化到具体物品。生成式推荐用 teacher forcing 训练，推理时却要以自己的预测为条件（exposure bias）。论文把这个问题在 SID 上的表现命名为 **Semantic Drift**：首层或第二层走错之后，后面每一步都在错误的物品簇里搜索，无法回头，模型还会退回训练数据的边际分布，偏向热门物品。

作者把 SID 路径类比为 LLM 的思维链，把数学推理里的 **过程奖励模型（PRM）** 搬过来，对每一步的中间路径打分：

- **Path-level PRM**：与生成主干端到端联合训练，输入 (用户, 上下文, 长度为 b 的 SID 前缀)，输出一个标量分；用正前缀和均匀采样的负前缀做逐层 InfoNCE。
- **PRM-guided Beam Search**：每步 decoder 先保留 K+ ≫ K 条候选，PRM 打分后只留 K' 条进入下一步。K' = K 时 decoder 计算量不变，于是增大 K+ 就成了一个只花少量额外算力的 **test-time scaling** 旋钮。

## 整体实现思路

1. **生成主干**：标准 encoder-decoder。encoder 编码用户历史序列得到 E(L)；decoder 逐层预测 SID，第 b 层隐状态和第 b 层码本 C_b 做点积再 softmax，NTP 损失为 d 层负对数似然之和。
2. **PRM 分支**：复用 encoder 输出 E(L) 作为 key/value，每条候选路径压成一个 query token，经 1 层（工业设置）cross-attention + FFN + MLP 得到分数。
3. **联合训练**：L_total = L_NTP + Σ_b L_InfoNCE(b)。
4. **推理**：Algorithm 1，每步「decoder top-K 扩展 → 按 log-prob 选 K+ → PRM 打分选 K'」，共 d 步。
5. **部署**：线上 K+ = 4000，K = K' = 1000，PRM 头数为主干的 1/4，用 Radix Top-K 加速大候选集的 top-k。

## 子模块实现（可复现细节）

### 1. 正样本定义

目标物品 x_t 的 SID 为 [s_{t,1}, …, s_{t,d}]。第 b 层的正样本是其长度为 b 的前缀：S_pos(x_t, b) = [s_{t,1}, …, s_{t,b}]，b ≤ d。理由是在残差量化下，要召回深度 d 的完整路径，必须先召回深度 d−1 的前缀。

### 2. 负采样

量化码本空间远大于物品数，不是所有 SID 组合都对应真实物品。记 V_b 为长度 b、能对应到真实物品的**合法路径集合**。每个正样本、每一层，从 V_b \ {S_pos} 中**均匀**采 N 条互不相同的负路径：

N(x_t, b) = { S_neg_i ~ Uniform(V_b \ {S_pos(x_t,b)}), i = 1..N }

正文未给出 N 的具体值。

### 3. PRM 结构

- 路径表示：P_S = EmbLookup([s_1, …, s_b])。**每条前缀路径映射成一个独立向量**，不按 token 序列编码，以减少 attention 计算。
- 交互：P_S 作 query，encoder 最终输出 E(L) 作 key/value，堆 F 层：
  - P' = P + CrossAttn(P, E(L), E(L))
  - P = P' + FFN(RMSNorm(P'))
- 输出：y_S = MLP(P_S^(F))，一个标量 logit。
- 工业设置 F = 1；线上 PRM 注意力头数为主生成模块的 1/4；所有候选 query 并行计算。

### 4. 训练目标

第 b 层：

L_InfoNCE(b) = −log [ exp(y_pos) / ( exp(y_pos) + Σ_{neg∈N(x_t,b)} exp(y_neg) ) ]

d 层相加，再与 NTP 直接相加：L_total = L_NTP + L_InfoNCE（无权重系数）。

### 5. PRM-guided Beam Search（Algorithm 1）

```
B(0) = {[BOS]}, S(0) = {0}
E = Encoder(history)
for b in 1..d:
    C = {}
    for path P in B(b-1) with score s:
        p = softmax(Decoder(P, E) · C_b^T)
        for top-K tokens (s_k, p_k): C += (P ⊕ s_k, s + log p_k)
    C_K+ = top-K+ of C by log-prob score
    Y = PRM(u, c, C_K+)           # 并行打分
    B(b) = top-K' of C_K+ by Y    # 保留的分数仍是累计 log-prob
return B(d)
```

直接把传统 beam 的 K 加大，decoder 每一步的 self-/cross-attention 计算量都线性增加；而 PROMISE 中 K' = K 时 decoder 成本不变，额外开销只有 K+ 条路径的单层 cross-attention 和更大的 top-k。

### 7. 诊断指标 HRecall@b@k

S(b) 为真值物品 SID 的 b 层前缀集合，B(b) 为第 b 步 beam 中保留的 k 条路径：

HRecall@b@k = |B(b) ∩ S(b)| / |S(b)|

b = d 时等于普通 Recall@k。用它可以看出漂移发生在哪一层。

## 思考与可参考价值

**值得借鉴的地方**

1. **先诊断再动手**：HRecall@b@k 能直接告诉你 SID 链路在哪一层丢了目标。快手数据上第 1 层约 92%，第 2 层掉到约 37%，说明真正的瓶颈在中间层。电商 SID 召回或搜索可以先跑这个指标。
2. **“扩宽 + 轻量剪枝”是一个通用推理旋钮**：decoder 成本不变，只靠一个单层 cross-attention 打分器就能换来召回提升，适合延迟预算紧的线上场景。K+ 可以按流量分层或按时段动态调整（推断）。
3. **PRM 是插件**：它复用 encoder 输出、与主干联合训练，不改 decoder，和前缀合法性约束、Q-Former 压缩历史、指针机制等改造是正交的，可以叠加（推断）。

**需要警惕的地方**

1. **基线口径**：同主干、传统 beam 下的 Recall@1000 只有 0.2296，明显低于 GRank 的 0.3178。PRM 的大部分收益是在补齐生成式自身的漂移损失；对 GRank 的净增益只有 +5.66%（K+=4000）。落地前要先确认自家生成式模型和现有最强召回的差距。
2. **负样本分布不匹配**：训练用的是从合法路径均匀采样的“容易”负例，推理时却要在 decoder 给出的高概率候选里分辨好坏。建议补做 beam 内难负例、同父节点兄弟负例的对比实验。
3. **路径嵌入表**：EmbLookup 给每条前缀一个独立向量。M = 8192、d = 3 时，可能的路径组合非常多，实际只能对合法路径建表（推断）。新物品带来的新路径怎么冷启动，论文没有说明。
4. **“Scaling law”说法偏强**：证据只是 K+ 在 1000~6000 之间 6 个点的单调上升，没有拟合曲线，也没有给出饱和点。
5. **线上收益偏小、配置不透明**：使用时长 +0.12%~0.13%，对照组的模型规模等细节未披露，也没有开源代码。

**一句话**：一个工程成本很低、思路清楚的 SID 推理期补丁。适合先在自家 SID 链路上用 HRecall 诊断，再小成本试 K+ 扩宽加 PRM 剪枝；不要把论文里相对弱基线的大幅提升当成预期收益。
