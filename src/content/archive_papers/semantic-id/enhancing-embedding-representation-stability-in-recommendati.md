## 核心思路

这篇在 Semantic ID 这条线里位置很特殊：**它完全不碰生成式检索**。SID 在这里不是解码目标，而是判别式排序模型（DLRM 架构）里 sparse feature 的**embedding 查表函数**，直接替掉随机哈希。

它的核心论点是：工业推荐里三个看起来各自独立的数据病其实是同一个病的三张脸。

- **物品基数**：真实物品数 I 远大于可行的 embedding 表大小 H，必须碰撞。
- **曝光长尾**：排序后 top 0.1% 的头部物品吃掉 25% 曝光，接下来 5.5% 的腰部吃 50%，剩下 **94.4% 的尾部只占 25%**。
- **ID 漂移**：广告每天新建、生命周期短，**初始物品池有一半在 6 天内退出系统**，同时等量新物品进来。

把这三条接起来就是作者真正要说的事：**随机哈希 + ID 漂移 = embedding 表示不稳定**。因为哈希碰撞是随机的，同一行 embedding 收到的是互相矛盾的梯度；又因为物品不断进出，老物品学到的东西被冲掉，新物品的权重本质上是随机的。一个 embedding 在不同时间代表着不同的物品。

SID 的解法不是「消除碰撞」而是**让碰撞变得有意义**：按内容语义做层级聚类，于是碰撞发生在语义相近的物品之间。好处顺着就出来了——尾部物品能蹭头部/腰部语义近邻的梯度；广告主下新广告时细节变了但品类通常没变，新旧广告的 SID 会共享前缀，所以**语义概念的时间稳定性直接转化成 ID 空间的时间稳定性**。

## 整体实现思路

两阶段拿 SID：多模态内容理解模型（图文对齐预训练，CLIP 式）产出 dense content embedding → 在上面训 RQ-VAE 得到 L 层粗到细的离散码 `(c1, ..., cL)`。

然后是本文真正的新东西：**token 参数化**，即怎么把这串码映射到 embedding 表的行号 `p(c; H): K^L → [1..H]^G`。这一步被作者认为是把 SID 用进排序模型的关键，也是原始 SID 工作（Singh et al. 2023）没做好的地方。

直觉是：`c1` 是最粗的桶（比如「食物类广告」），`(c1,c2)` 细化到「披萨」，`(c1,c2,c3)` 再细化到「英文写的披萨广告」。所以参数化方案决定了**模型能看到多粗/多细的语义信息**，而全部细粒度组合（所有 `(c1..cL)` 元组）往往因为基数爆炸不可行——这里存在一个基数与信息量的 tradeoff。

## 子模块实现（可复现细节）

**RQ-VAE**。残差 `r_l := z - Σ_{i<l} v_{c_i}^i`，`c_l := argmin_c ||v_c^l - r_l||²`。损失是重建项加 commitment 项：`L = ||x - dec(c)||² + Σ_l ( β||r_l - sg(v_{c_l}^l)||² + ||sg(r_l) - v_{c_l}^l||² )`，实验里 **β = 0.5**。每层码本大小相同，共 `K^L` 个簇。

**几种 token 参数化**（论文 Table 1）：

| 方案 | 映射 |
|---|---|
| Trigram | `[K²c1 + Kc2 + c3]` |
| Fourgram | `[K³c1 + K²c2 + Kc3 + c4]` |
| All bigrams | `[K²(i−1) + Kc_i + c_{i+1}, i ∈ 1..L−1]` |
| **Prefix-ngram** | `[Σ_{t=1..i} K^{i−t}(c_t + 1) − 1, i ∈ 1..n]` |

关键区别：**只有 Prefix-ngram 同时包含所有粒度的前缀**——`c1`、`(c1,c2)`、…、`(c1..cn)` 各自占一个 embedding 行，模型 sum-pooling 这 n 行。其余方案都是单一粒度的扁平映射。SID 基数超过表大小时再套 modulo hash；多个 ID 并存时加 shifting factor 避免跨位置碰撞。

**参数化消融（Table 2，Train NE Gain，越负越好）**：

| RQ-VAE K × L | 参数化 | Train NE Gain |
|---|---|---|
| 2048 × 3 | Trigram | −0.028% |
| 2048 × 4 | Fourgram | −0.035% |
| 2048 × 4 | All bigrams | −0.091% |
| 512 × 3 | Prefix-3gram | −0.034% |
| 1024 × 3 | Prefix-3gram | −0.097% |
| 2048 × 3 | Prefix-3gram | −0.141% |
| 2048 × 5 | Prefix-5gram | −0.208% |
| 2048 × 6 | Prefix-6gram | −0.215% |

三条结论：Prefix-ngram 最好（层级信息必须显式进 embedding 映射，扁平映射的知识共享范围太窄）；加深 n 持续变好；加大码本基数也持续变好。

**模型与指标**。DLRM 三段式（信息聚合 → 交互层做两两点积 → MLP 出 logit），交叉熵训练，本文只动信息聚合段。指标是 **NE（Normalized Entropy）**：模型交叉熵除以「按正样本均值频率预测」的交叉熵，越低越好。用户历史模块把交互序列过一个聚合模块，三种选择：**Bypass**（逐位置线性，不做上下文化）、**Transformer**、**PMA**（Pooled Multihead Attention，Set Transformer 那套，T=32）。历史覆盖三个月、物品基数超 10 亿、序列长度 O(100)。

**离线实验配置**。简化版 Meta 广告排序模型：保留全部 dense 特征和用户历史，sparse 侧只留 target item（去掉 O(100) 个其他 sparse 特征）。按时间顺序训 4 天数据、单 epoch，在次日前 6 小时上评。三个对照：**IE**（每个 raw ID 独占一行，`I = H`，不可生产但作上界参考，未见过的 ID 映到随机未训练行）、**RH**（随机哈希，平均碰撞因子 3）、**SemID**（L=3、K=2048、prefix-3gram，同样碰撞因子 3）。用户历史侧仍用随机哈希，以隔离 target item 的效果。

**生产配置**。RQ-VAE 训在内部 Content Understanding 模型上（CC100 预训练 + 广告数据微调），取过去三个月的广告 ID 和内容 embedding；**生产用 L=6、K=2048、prefix-5gram、H = O(50M)**，训完冻结 checkpoint 用于在线服务。服务链路：广告创建时过 CU 模型 → RQ-VAE 算 SID → 写入 Entity Data Store → 特征生成阶段把 target item 和用户互动历史的 raw ID 用 SID 富化 → 线上请求直接取预计算特征。

## 实验设置与结果

**分段分析（Table 3a，Eval NE）**。头/腰/尾按累计曝光 25%/75%/100% 切，对应物品占比 0.1%/5.6%/100%：

| 分段 | RH | IE | SemID | vs RH | vs IE |
|---|---|---|---|---|---|
| 头部 | 0.80105 | 0.80101 | 0.80108 | 0.00% | +0.01% |
| 腰部 | 0.83589 | 0.83583 | 0.83580 | −0.01% | −0.00% |
| 尾部 | 0.83904 | 0.83886 | 0.83872 | −0.04% | −0.02% |
| 训练中见过的物品 | 0.82626 | 0.82612 | 0.82600 | −0.03% | −0.02% |
| **新物品（冷启）** | 0.83524 | 0.83453 | 0.83180 | **−0.41%** | **−0.33%** |
| 全部 | 0.82663 | 0.82645 | 0.82621 | −0.05% | −0.03% |

增益几乎全来自长尾和冷启动，头部完全中性。注意 SemID 连 **IE 都打赢了**——这说明它不只是「比随机哈希聚得好」，而是语义知识共享本身在提供额外信息，这是全文最硬的一个证据。

**分布漂移敏感度（Table 3b）**。拿训好的模型回头评训练数据的两个时间段：`NE[42–48h 前] − NE[最后 6 小时]`，差值越小说明受 embedding 表示漂移影响越小。全物品：RH 0.0083 / IE 0.0074 / **SemID 0.0073**。SemID 追平了 IE，而 RH 明显更差——印证了「随机哈希的 embedding 随时间失去表示老物品的能力」。

**长周期训练（Table 4）**。从 4 天数据加到 20 天，Eval NE 增益 RH −0.18% vs **SemID −0.23%**：SID 随数据量 scale 得更好，因为周期越长 ID 漂移越严重。

**表示空间分析（Table 5）**。把 IE 学到的逐物品 embedding 按 RH 和 SemID 两种方式分区（碰撞因子 5），比较簇内方差和簇间距离：

| 分区 | 簇内方差 | 簇间两两距离 |
|---|---|---|
| Random Hashing | 1.52e−3 (8.0e−4) | 0.22 (0.04) |
| SemID（小簇 4–10 个物品） | 1.31e−3 (1.0e−3) | 0.24 (0.09) |
| SemID（top 1,000 大簇） | 1.23e−3 (5.5e−4) | **0.06 (0.02)** |

簇内方差 SemID 更低（更好的「摘要」），但**簇间距离给出矛盾信号**：top 1,000 大簇之间距离只有 0.06。作者自己的解释是 RQ-VAE 为了压重建损失会把多个质心塞进数据最密的区域——这其实就是码本分配不均的老问题，论文坦白写了但没解决。

**用户历史建模（Table 6，把 SID 用在历史特征上）**。基线是三个模块都用 RH：

| 聚合模块 | Train NE Gain | Eval NE Gain |
|---|---|---|
| Bypass（不做上下文化） | −0.056% | −0.085% |
| Transformer | −0.071% | −0.110% |
| PMA | −0.073% | −0.100% |

SID 给**会做上下文化的注意力模块带来更大增益**。注意力指标（Table 7）给了机制层面的解释：SemID 模型的注意力熵更低（不那么弥散）、padding token 注意力更低（Transformer 0.460 → 0.418）、self-attention 更低（0.052 → 0.045）、首位（最近一个物品）注意力更高（0.030 → 0.043）。即注意力更集中在高信号 token 上。

**生产效果（Table 8）**。做了 6 个 sparse + 1 个 sequential 特征（文本/图像/视频三种内容源）。旗舰广告排序模型上：6 个 sparse 特征 Train/Eval NE −0.063%/−0.071%；1 个 sequential 特征 −0.110%/−0.123%。Meta 广告排序里离线 NE 增益 > 0.02% 就算显著。**跨多个排序模型，顶线在线指标累计 +0.15%**，已上线一年多，按特征重要性排进 top sparse features。

**语义相似 → 预测相似（7.4）**。在线 A/B：50% 概率把推荐集合 S 里的一个物品换成**同 SID 前缀的另一个物品**，测 `Click Loss Rate := (CTR on S' − CTR on S) / CTR on S`。前缀越深，click loss rate 单调下降——说明 SID 的层级确实捕捉到了越来越细的语义，且预测相似性与语义相似性相关。

**A/A 方差（7.5）**。同一个广告复制一份换个 raw ID，随机哈希下两份会落到不同 embedding，模型预测和投放行为就不一样，这叫 A/A 方差。定义 `AAR(a1,a2) := 2|p(a1) − p(a2)| / (p(a1) + p(a2) + ε)`。带 6 个 SID sparse 特征的生产模型**平均 AAR 降低 43%**。作者认为主要来自尾部物品。这条对广告主信任度和排序稳定性是实打实的业务价值。

## 思考与可参考价值

**可借鉴**

1. **Prefix-ngram 这个 trick 几乎零成本，而且与生成式无关，判别式模型可以直接用**。我们现在在判别式侧用 SID 时如果只喂最细一级的拼接码（等价于 Trigram/Fourgram），按 Table 2 的幅度，换成 prefix-ngram 大概是 2–6 倍的 NE 增益（−0.035% → −0.215%）。改动只是把「一个 ID」变成「n 个前缀 ID 的 sum-pooling」。
2. **「SemID 打赢 IE」这个对照设计值得抄**。一般做法是只比随机哈希，赢了就说明聚类有用；加上 individual embedding 这条上界后，才能区分「碰撞变好了」和「语义共享带来了新信息」。我们评 SID 时基本没设这条上界，建议补。
3. **SID 的时间稳定性是个被低估的卖点**。我们看 SID 时主要看召回/排序指标，没有量化过「同一行 embedding 的语义是否随时间漂移」。这篇给了两个很轻的量化口径，都不需要重新训练：（a）训完的模型回头评更早时间段的 NE 差；（b）A/A 方差——复制一个 item 换 ID，看预测差异。后者对电商尤其合适，同款商品不同 SKU/不同店铺上架就是天然的 A/A 对。
4. **SID 与注意力结构有交互效应**：对会做上下文化的模块（Transformer/PMA）增益明显大于不做上下文化的 Bypass。这暗示我们在 last20/last100 这类历史序列建模里把 SID 作为历史 token 的表示，收益可能比在 target 侧更大——这个方向我们还没系统试过。
5. **分段看增益来源**。头部中性、尾部和冷启起飞（新物品 −0.41%），这个分布很可能在我们场景复现。如果整体指标只动一点点，应该先按曝光分段看，而不是直接判定无效。
6. **RQ-VAE 质心聚堆这个问题被实测确认了**：top 1,000 大簇之间两两距离只有 0.06，远低于随机分区的 0.22。这与我们在码本利用率上遇到的问题是同一件事，可以拿这篇当外部证据。

**落地前要核对**

- 全是 Meta 广告内部数据和 NE 口径，**没有公开基准、没有代码**，绝对数字不可迁移。
- 增益幅度按绝对值看非常小（离线万分之几，线上 0.15%），只有在 Meta 这种体量和优化程度下才算显著；小体量系统上这个量级可能淹没在噪声里。
- 关键混杂项没拆：SemID 的收益里有多少来自**内容理解模型本身带来的多模态信息**，而不是「稳定 ID 空间」这个机制？论文没有「用同样内容 embedding 但随机分簇」的对照，所以「语义碰撞」与「内容信息注入」两种解释无法区分。这是我觉得最该补的实验。
- RecSys 2025 正式版只有 4 页（p.954–957），是短文；完整论证只在 arXiv 版里，引用时要注意。
- prefix-ngram 把单个 ID 变成 n 个查表，**embedding 表容量和查表开销都要乘 n**（生产配置 H = O(50M)），不是真的免费。
- 冻结 RQ-VAE checkpoint 上线意味着码本不随分布更新，论文没讨论什么时候需要重训码本、重训时如何平滑切换——这对我们按天增量训练的场景是个现实问题。

## 一句话评价

Meta 广告的 SID 工程实践论文，立论是「随机哈希 + ID 漂移导致 embedding 表示不稳定」，用语义碰撞替代随机碰撞，核心技术贡献是 Prefix-ngram 参数化（把所有粒度前缀一起喂给模型，离线 NE 从 −0.028% 拉到 −0.215%）。增益集中在长尾和冷启（新物品 −0.41%，且打赢 individual embedding 上界），线上一年多累计顶线 +0.15%、A/A 预测方差降 43%。纯内部数据、增益绝对值小、且没有「同内容 embedding 随机分簇」的关键对照；但 prefix-ngram 和两个稳定性量化口径（回看更早时段的 NE 差、A/A 方差）都是能立刻拿走用的东西。
